Custom Touchscreen Kiosk

Custom kiosk software that turns a standard Portworld touchscreen panel into a branded, configurable, and recoverable ASTEL product.

Embedded Linux Chromium Kiosk Flask JavaScript Bash systemd

01

Starting point

I started with a standard Portworld YC-SM41P touchscreen panel running the manufacturer's Debian image. The hardware worked, but the system was not ready to be used as a dedicated product.

I removed unnecessary startup services and configured the device to launch directly into the kiosk, reducing the time needed to reach the graphical system.

6.1s Original graphical startup
4.4s Optimized graphical startup

02

Building the kiosk mode

I created a custom Linux session that automatically launches Chromium in fullscreen kiosk mode. Before opening the configured website, the session waits for a network connection and verifies that the system clock is valid, preventing connection and certificate errors during startup.

The unusual 480×480 display introduced several layout problems. I fixed incorrectly sized Chromium windows, hidden content, cursor visibility, and unwanted touchscreen pinch-to-zoom.

03

Creating the setup interface

To make installation and configuration simple, I built a local setup interface using Flask, HTML, CSS, and JavaScript. It is designed specifically for the small square touchscreen and works without an external keyboard or computer.

  • Select and connect to a WiFi network
  • Configure and test the kiosk URL
  • Adjust screen brightness
  • Select an ASTEL Lighting or ASTEL Marine boot logo
  • Reboot or shut down the device

04

Solving hardware-specific problems

The WiFi module regularly attempted to use WPA3 on mixed WPA2/WPA3 networks, causing long connection timeouts. I fixed this with explicit WPA2 profiles and added a small system service to work around a separate firmware association delay.

Together, these changes reduced cold-boot WiFi connection time and made the complete kiosk visible roughly ten seconds sooner than at the start of the project.

19s Original cold-boot WiFi
10.5s Optimized cold-boot WiFi

05

Branding and device controls

I replaced the default boot graphics with ASTEL branding. Because the logo is stored inside a verified Rockchip boot partition, I created a guarded flashing tool that safely updates both the image and its integrity hash.

The panel has one accessible hardware button, so I gave it two deliberate recovery functions without exposing the Linux desktop.

Short press

Refreshes the displayed web page.

Three-second hold

Clears settings and returns the device to setup mode.

06

Deployment and recovery

The project began with manual testing on one device. As it stabilized, I moved the configuration, scripts, services, and interface into a structured repository and created a repeatable deployment process.

Fresh devices can be prepared over ADB, while later updates deploy over SSH. The same process works from Linux and Windows and includes backups and checks for boot-critical changes.

During development, raw image restoration erased the device's boot chain. I recovered it using the board's MaskROM pins and the manufacturer's official image. The final process therefore uses the official image followed by automated deployment instead of unsafe raw image flashing.

07

Result

The finished system turns a standard touchscreen panel into a dedicated ASTEL kiosk that is branded, configurable, recoverable, and straightforward to deploy.

The project combined embedded Linux configuration, frontend development, systemd services, hardware debugging, network troubleshooting, and deployment automation.
